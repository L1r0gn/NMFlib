# NMFlib Topic Modeling MVP

用 NMFlib 完成一次完整的文档主题建模：原始文本 → 词频矩阵 → NMF 分解 →
主题关键词 / 稀疏度 / 文档主题激活 → 新文档 `transform` 推理。
纯 MoonBit 实现，只依赖 core 与 NMFlib 现有公开 API，零生产代码改动。

## 这个示例解决什么问题

给定一批短文档，在**不使用任何标签**的前提下，自动发现其中反复出现的词语组合
（主题），并回答两个问题：

1. 每篇文档主要在谈哪些主题？
2. 一篇从未见过的新文档属于哪个主题？

## 什么是 Topic Modeling，NMF 扮演什么角色

主题建模假设文档由若干潜在主题混合而成，每个主题是词汇表上的一个权重分布。
NMF 把非负的文档—词语矩阵分解为两个非负因子的乘积：

```text
V ≈ W · H
```

| 矩阵 | 含义 | 维度 |
|---|---|---|
| V | 文档—词语矩阵（词频） | 文档数 m × 词汇数 n |
| W | 文档—主题矩阵 | m × 主题数 k |
| H | 主题—词语矩阵 | k × n |

**本示例使用文档 × 词语方向**：V 的行是文档、列是词。因此 W 的第 i 行是第 i 篇
文档在各主题上的激活强度，H 的第 j 行是第 j 个主题中各词语的权重。非负性让分解
结果天然可解释为"词语的叠加组合"，而不是正负抵消的抽象基。

## 文档如何变成词频矩阵

- 语料：`corpus.mbt` 中 15 篇固定 lowercase 英文短文档（科技 / 体育 / 烹饪各 5 篇，
  其中 3 篇为混合主题），外加 3 篇用于 `transform` 的新文档。语料内置于源码，
  不下载任何外部数据。
- tokenizer：按空白字符（空格 / `\t` / `\n` / `\r`）切分，丢弃空 token。
  不做词干提取、词形还原、停用词、TF-IDF。
- 词汇表：**按语料中首次出现的顺序**构建（确定性、可复现），共 18 个词。
  查找用线性扫描——十几篇文档的规模不需要 Map/Trie。
- `V[i][j]` = 第 i 篇文档中第 j 个词的出现次数（Double）。构造后自检：
  维度 15×18、全部非负有限、无全零行、无全零列。

`corpus.mbt` 中的 `expected_labels` 只是人工解释参考，**不参与** tokenizer、
词汇表、V 或 NMF 训练的任何环节。

## 为什么 MU + Generalized KL

词频是非负计数数据，广义 KL 散度 `D(V‖WH) = Σ[V·log(V/WH) − V + WH]` 是适合
计数数据的目标函数之一（对低频词的相对误差更敏感，不像 Frobenius 那样被大计数主导）。
MU-KL 组合已在 T16 中与 scikit-learn 做过独立参考验证。

## 为什么 Random 初始化

T16 验证发现：MU + NNDSVD 在含结构零的矩阵上可能把初始零元素"零锁定"，
导致 `V>0 ∧ WH=0` 的 NumericalError。词频矩阵天然充满结构零（每篇文档只用到
少数词），因此本示例优先使用 Random 初始化（固定 seed=42，逐位可复现），
不把已知风险带进基础应用示例。

## 模型配置与 L1 参数选择

```moonbit
let config = @nmf.NMFConfig::new(
  n_components=3, solver=MU, loss=KLDivergence, init=Random,
  max_iter=500, tol=1.0e-4, seed=42UL, l1_reg=0.001, l2_reg=0.0,
)
```

L1 正则 `λ1·(ΣW + ΣH)` 以梯度形式进入 MU 更新，推动因子收缩、抑制无关词的权重。
参数不是拍脑袋定的：在同一语料、同一 seed 下对 `λ1 ∈ {0, 1e-4, 1e-3, 1e-2}`
做了有限扫描，每次分别记录重构误差、数据 KL、正则惩罚、完整目标、H 平均 Hoyer
稀疏度与 Top-6 关键词（**不同 λ1 对应不同优化目标，完整 loss_value 之间不可直接
比大小**；下表并列展示只是为了观察各自的行为）：

| λ1 | recon error (Frobenius) | 数据 KL | L1 惩罚 | 完整 loss_value | H 平均 sparsity | n_iter |
|---|---|---|---|---|---|---|
| 0 | 4.9517272 | 21.7309409 | 0 | 21.7309409 | 0.56248870 | 12 |
| 1e-4 | 4.9517265 | 21.7309409 | 0.0044847 | 21.7354257 | 0.56248870 | 12 |
| **1e-3** | **4.9517203** | **21.7309415** | **0.0447405** | **21.7756820** | **0.56248870** | **12** |
| 1e-2 | 4.9516891 | 21.7303650 | 0.4364520 | 22.1668170 | 0.56249661 | 13 |

四个设置下三个主题都完整保留各自的 6 个特征词，无主题塌缩；每行均验证了
`loss_value = 数据KL + L1惩罚` 精确成立。选择 **1e-3** 的依据：

- 1e-4 的效应接近噪声（惩罚仅 0.0045，关键词权重变化 ~0.04%）；
- 1e-3 产生可测量的收缩（Top 词权重约收缩 0.4%，如 `network` 2.5596 → 2.5488），
  重构误差与数据 KL 在 5 位有效数字内不变，主题可解释性不受影响；
- 1e-2 收缩约 4%，但没有带来额外的可解释性收益。

即"最小的、能体现正则效果且不造成主题塌缩的非零参数"。需要如实说明：这个语料
主题分离非常干净，H 本身已经稀疏，四个设置下 H 的 Hoyer 稀疏度都稳定在 ≈0.5625，
L1 在此主要表现为权重收缩而非稀疏度大幅上升——本示例的目的不是证明 L1 越强越好，
而是展示如何合理使用正则化。

## 如何运行

在仓库根目录：

```sh
moon run examples/topic_modeling
```

程序依次打印 7 个环节的报告，每个环节带运行时自检（维度、非负、有限、无全零
行列、sparsity 范围、transform 前后 H 不变等）；任何检查失败立即 `abort` 报错，
不会继续打印伪造结果。

## 实际运行结果（seed=42，本地工具链 0.1.20261028 真实输出）

训练：12 次迭代收敛；完整目标 `loss_value = 21.775682048872746`（含正则项）；
重构误差 `‖V−WH‖_F = 4.951720277412234`（Frobenius 范数，不含正则项，两者不可混淆）。

发现的三个主题（Top-6 关键词，权重来自真实的 H）：

```text
Topic 0                      Topic 1                      Topic 2
network       2.5488         food          2.3655         match         2.2997
data          2.5486         recipe        2.3655         player        2.2997
digital       2.124          kitchen       2.3655         coach         1.9164
computer      2.124          ingredient    1.9712         team          1.9164
software      2.1235         flavor        1.9712         score         1.9164
processor     1.2744         oven          1.577          stadium       1.5331
```

**人工解释（仅限本次运行）**：Topic 0 = 科技，Topic 1 = 烹饪，Topic 2 = 体育。
NMF 的分量顺序不固定：换 seed 或换数据后编号可能重排，程序始终动态打印
Topic 0/1/2，由人根据关键词解释，代码不做任何强制对应。

每个主题的 Hoyer 稀疏度（对 H 的**每一行**单独调用公开 API `@nmf.sparsity`）：

```text
Topic 0 sparsity: 0.5677
Topic 1 sparsity: 0.5602
Topic 2 sparsity: 0.5596
Average topic sparsity: 0.5625
```

Hoyer 稀疏度 `S(x) = (√n − ‖x‖₁/‖x‖₂)/(√n − 1)` 越接近 1，主题权重在词汇维度上
越集中；越接近 0 越均匀。它是**稀疏度指标，不是主题准确率或质量评分**。
平均值只在示例内部计算，不是库 API。

文档主题激活（W 行归一化，`p_ij = W_ij / Σ_t W_it`）：12 篇单主题文档的 dominant
topic 全部与人工预期类别一致；3 篇混合文档呈现合理的混合激活——

```text
Document 4  [科技+体育]   -> Topic 0 (0.5542) + Topic 2 (0.4458)
Document 9  [体育+烹饪]   -> Topic 2 (0.5861) + Topic 1 (0.4139)
Document 14 [烹饪+科技]   -> Topic 1 (0.7164) + Topic 0 (0.2836)
```

注意：这是 **normalized activation（相对主题激活）**，只是模型因子激活的相对占比，
**不是经过概率校准的统计概率**。

## 新文档 transform

`transform` 固定训练得到的 H，只对新输入优化 W，不重新训练：

```text
新文档 → 同一 tokenizer → 同一词汇表 → 新词频矩阵 → model.transform → 主题激活
```

3 篇新文档各含 2 个 OOV 词（如 router / cloud / referee / microwave / simmer）：
OOV 被计数并忽略，词汇表不扩充（扩充会使 H 的特征维度失配）。若某篇新文档的词
全部是 OOV（去除后为全零向量），程序会明确报告并跳过主题解释，不静默归类；
已知词存在但统计结果异常则直接报错。本次运行结果：

```text
New document 0 (偏科技) -> Topic 0，激活 1.0
New document 1 (偏体育) -> Topic 2，激活 1.0
New document 2 (偏烹饪) -> Topic 1，激活 1.0
```

示例在 transform 前后对 H 做逐元素快照对比，确认训练 H 未被修改；并检查返回的
W_new 维度为 3×3（新文档数 × rank）、非负且有限。新文档选词均落在训练主题词汇的
表示范围内，避免 T11 文档化的 KL transform NumericalError（`V>0 ∧ WH=0`）；
不通过加 epsilon 或改 H 绕过数值错误。

## 限制

- 语料极小（15 篇、18 词）且主题分离干净，结论不能外推到真实大规模语料；
- tokenizer 只是空白切分，无词干/停用词/TF-IDF，不代表工业级 NLP 系统；
- rank=3 是人工选择的，示例不演示 rank 自动确定；
- 主题编号不固定，主题解释依赖人工阅读关键词；
- W 的归一化是相对激活，不是严格概率；H 权重用于解释主题词，不是词的重要性真值；
- Hoyer sparsity 是稀疏度指标，不是主题质量评分；
- OOV 处理较基础：计数并忽略，不做子词回退或词汇表扩展。
